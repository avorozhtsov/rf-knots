# How a knot is represented, and what the agent is allowed to do to it

This is the reference for the environment's mathematics. Everything here is
enforced in code and checked in tests; where a claim is verified by a specific
test, the test is named.

---

## 1. Why braid words

A knot is a circle embedded in 3-space. To put one in an array you need a
combinatorial presentation, and the candidates are:

| presentation | what it is | why not / why yes |
|---|---|---|
| planar diagram (PD code) | list of crossings, each with 4 edge labels | moves are local, but validity is a *global* constraint; fixed-shape JAX arrays fight it |
| Gauss / DT code | sequence of crossing visits | compact, but a random code is usually not realisable as a planar diagram |
| grid / arc presentation | knot on a grid, finite clean move set | genuinely good; second choice |
| **braid word** | word in the braid group, knot = its closure | **used here** |

The braid word wins on three counts that matter for a vectorised RL environment:
its state is a flat integer array of fixed length, every move is a *local rewrite*
at one position, and the move set is finite and complete (§5).

## 2. The braid group `B_n`

`B_n` is generated by `σ₁, …, σ_{n-1}`, where `σᵢ` exchanges strands `i` and
`i+1` with strand `i` passing **over**, and `σᵢ⁻¹` with it passing **under**.
The defining relations are

```
(R2)   σᵢ σᵢ⁻¹ = e                                    free reduction
(FC)   σᵢ σⱼ   = σⱼ σᵢ            for |i − j| ≥ 2     far commutation
(R3)   σᵢ σᵢ₊₁ σᵢ = σᵢ₊₁ σᵢ σᵢ₊₁                       braid relation
```

A braid word is drawn top to bottom, one crossing per letter. `docs`-quality
pictures are produced by `rf_knots.render.braid_svg`.

### The closure

Join the bottom of each strand to the top of the same strand around the right of
the diagram. The result is a link — this is the **closure** `cl(w)`, and it is
the object the environment actually cares about. Two facts make this usable:

* **Alexander's theorem.** Every link is the closure of some braid. Nothing is
  lost by working only with braids.
* **Markov's theorem.** `cl(w) = cl(w')` as links **iff** `w` and `w'` are
  related by a finite sequence of: equality in the braid group, *conjugation*,
  and *stabilisation / destabilisation*. This is what makes the move set of §4
  complete rather than merely sound.

### Components: knots versus links

The closure of `w ∈ B_n` has one component per cycle of the underlying
permutation (map each letter `±i` to the transposition `(i, i+1)` and multiply).
The identity braid in `B_n` closes to the **n-component unlink**, not the unknot
— which is why the environment's trivial state is `n = 1` with an empty word, and
why component count is checked on every single step
(`test_moves_preserve_the_number_of_components`). A knot is exactly a
1-component closure.

## 3. The array encoding

```
word : int32[L]      left-compacted, 0 is padding
n    : int32         active strand count, 1 ≤ n ≤ N
```

`+g` means `σ_g`, `−g` means `σ_g⁻¹`, `0` means "no letter". The invariant held
everywhere is

```
word[k] ≠ 0  for k < length          word[k] = 0  for k ≥ length
1 ≤ |word[k]| ≤ n − 1
```

`length` is never stored — it is `sum(word ≠ 0)`, exact because the word is
compacted. Storing it would only create a way for it to fall out of sync.

`L` (`max_len`) and `N` (`max_strands`) are the capacity knobs. `L` must be
generous: simplifying a hard instance often requires *lengthening* the word
first, and an instance that would need more than `L` letters becomes
artificially unsolvable rather than mathematically hard.

## 4. The moves

Three tiers, distinguished by what they preserve.

### Tier 1 — braid-group moves: preserve the element of `B_n`

These are the relations of §2 read as rewrites. They change the word but not the
braid, so *a fortiori* not the closure.

| move | rewrite | legal when | Reidemeister |
|---|---|---|---|
| `REDUCE(p)` | `… a  −a …` → `… …` | `word[p] = −word[p+1] ≠ 0` | **R2** (undo) |
| `INSERT(p,g,s)` | `… …` → `… v  −v …`, `v = s·g` | `length + 2 ≤ L`, `p ≤ length`, `g ≤ n−1` | **R2** (do) |
| `COMMUTE(p)` | `… a b …` → `… b a …` | `‖a| − |b‖ ≥ 2`, both ≠ 0 | planar isotopy, *not* a Reidemeister move |
| `BRAID(p)` | `… a b a …` → `… b a b …` | `‖a| − |b‖ = 1`, `sign a = sign b`, `word[p+2] = word[p]` | **R3** |

`BRAID` is implemented only for same-sign triples, which covers the positive
relation and its inverse, the all-negative one. The mixed-sign forms are
**derivable**, so nothing is lost — e.g. `(−b, a, b) → (a, b, −a)` in three
moves:

```
(−b, a, b)                    INSERT(a, −a) at the end
(−b, a, b, a, −a)             BRAID at position 1:  (a,b,a) → (b,a,b)
(−b, b, a, b, −a)             REDUCE at position 0
(a, b, −a)
```

`test_mixed_sign_braid_relation_is_derivable` checks the identity holds; every
tier-1 move is checked to preserve the group element exactly via the **Artin
representation** (§6) in `test_braid_group_moves_preserve_the_group_element`.

### Tier 2 — Markov moves: preserve the closure, not the element

| move | rewrite | legal when | geometry |
|---|---|---|---|
| `ROTATE_LEFT` | `a·rest` → `rest·a` | `length ≥ 2` | conjugation: `a⁻¹(a·rest)a`; slides a crossing around the closure arc |
| `ROTATE_RIGHT` | `rest·a` → `a·rest` | `length ≥ 2` | conjugation, the other way |
| `DESTABILIZE` | `w σ_{n−1}^{±1}` → `w`, `n → n−1` | `n ≥ 2`, last letter is `±(n−1)`, and it is the **only** occurrence of `±(n−1)` | **R1** (undo a kink) |
| `STABILIZE_±` | `w` → `w σ_n^{±1}`, `n → n+1` | `n < N`, `length + 1 ≤ L` | **R1** (add a kink) |

The "only occurrence" condition on `DESTABILIZE` is Markov's condition
(`w` must lie in `B_{n-1}`), and it is what keeps the closure from silently
turning into a link.

### Tier 3 — the crossing change: changes the knot

| move | rewrite | legal when |
|---|---|---|
| `CROSSING_CHANGE(p)` | `word[p] → −word[p]` | `word[p] ≠ 0`, and the mode allows it |

This is the **unknotting move**: `u(K)` is the minimum number of crossing changes
needed to reach the unknot, over all diagrams. It is masked off entirely during
the scramble phase — otherwise instances generated "from the unknot" would no
longer be unknots, and the free ground truth would evaporate. It is available to
the Simplifier only when `allow_crossing_change` is set, which is the
unknotting-number mode rather than the Scrambler-vs-Simplifier game.

### `PASS`

Present only because Pgx requires a non-empty legal mask, and legal **only when
nothing else is** — which at any realistic `L` is never. Left always-legal it is a
strictly dominated instant-forfeit: an untrained Scrambler picked it on ply 1 in
about a third of self-play games, ending them immediately. (This benchmark
already guards against the same collapse in Go by masking `pass` for the opening
plies.)

## 5. Completeness, and where it stops

By Markov's theorem the tier-1 and tier-2 moves generate **all** of link
equivalence for closed braids: any two words with the same closure are connected
by some finite sequence of them. The environment is therefore not missing a move.

Two caveats, both real:

1. **Capacity.** Markov's theorem is unbounded; `L` and `N` are not. A connecting
   sequence that must pass through words longer than `L` or braids wider than `N`
   is unavailable. Track how often this bites before blaming the agent.
2. **Length, not existence.** Completeness says a path exists, not that it is
   short. Deciding whether a diagram can be untangled in `≤ k` Reidemeister
   moves, or with `≤ k` crossing changes, is **NP-hard**
   (de Mesmay–Rieck–Sedgwick–Tancer, SoCG 2019). That hardness is the reason
   there is anything for an agent to learn.

## 6. How correctness is verified

The likeliest failure mode is not a wrong theorem but a wrong array index, and a
wrong array index here produces beautiful, meaningless learning curves. Four
independent checks run over actual rollouts (`rf-knots selfcheck`):

1. **Differential.** Every move and every mask bit is compared against a
   list-based Python implementation with no index arithmetic in it.
2. **Exact braid-group equality.** The **Artin representation** sends `σᵢ` to the
   automorphism of the free group `F_n` with
   `xᵢ ↦ xᵢ x_{i+1} xᵢ⁻¹`, `x_{i+1} ↦ xᵢ`, others fixed. It is *faithful*, so
   two words are equal in `B_n` **iff** their images agree on every generator.
   That turns "did this rewrite preserve the braid?" into a decidable test rather
   than a heuristic invariant.
3. **Component count.** Every reachable state has exactly one closure component.
4. **Round trip.** Scrambled instances replay back to the empty 1-braid through
   the JAX environment along a path found by exhaustive breadth-first search.

Cheap non-invariants used only as fingerprints for deduplication: writhe (sum of
signs — changes under stabilisation), word length, strand count.

## 7. Action-space layout

With `L = max_len` and `N = max_strands`, the flat action space is

```
[0,          L)          REDUCE(p)
[L,         2L)          COMMUTE(p)
[2L,        3L)          BRAID(p)
[3L, 3L+2L(N-1))         INSERT(p, g, s)      index 3L + ((g-1)·2 + s)·L + p
+0                       ROTATE_LEFT
+1                       ROTATE_RIGHT
+2                       DESTABILIZE
+3                       STABILIZE_POS
+4                       STABILIZE_NEG
+5                       PASS
[.., ..+L)               CROSSING_CHANGE(p)
```

Total `3L + 2L(N−1) + 6 + L`; at `L=64, N=8` that is **1158** actions, of which
896 are insertions. The size does **not** depend on whether crossing changes are
enabled, so one policy head serves both modes.

The layout is block-major on purpose: a `1×1` convolution over a `1 × L` latent,
flattened channel-major, reproduces the per-position blocks in exactly this
order. That is what the positional policy head in `pgx_mcts_bench.networks`
exploits, and it is why the head carries no dependence on `L` — widening the word
is a data change, not an architecture change. The alignment is checked block by
block in `test_policy_head_blocks_align_with_the_action_space`, because a
permuted action space would train perfectly happily and mean nothing.

## 8. The game on top

```
phase 0 (Scrambler, K plies)   start from the empty 1-braid = the unknot.
                               apply K tier-1/tier-2 moves.
                               the closure is STILL the unknot, by construction.
phase 1 (Simplifier, M plies)  sees only the resulting word, not the history.
                               wins iff it reaches the empty 1-braid.
payoff                         +1 / −1, zero-sum.
```

`K` is the difficulty dial. The players do **not** alternate, which is why the
MCTS value backup flips sign on player change rather than on every ply.

Terminal test is `length = 0 and n = 1` — cheap and exact. Note the asymmetry
that makes this design work: deciding "is this word's closure the unknot?" is
hard (unknot recognition is in NP ∩ coNP, not known to be in P), but *generating*
a word whose closure is known to be the unknot is trivial. So the environment
never has to decide; it only ever generates from a known answer.

## 9. Worked example

`σ₁σ₂` in `B₃`. Permutation: `(1 2)(2 3) = (1 3 2)`, one cycle, so the closure is
a knot. It is the unknot, and the environment solves it in two moves:

```
B3: s1 s2        DESTABILIZE   (last letter is ±2 = ±(n−1), and it is the only one)
B2: s1           DESTABILIZE
B1: e            terminal
```

`σ₁σ₁` in `B₂` has permutation `(1 2)(1 2) = e`, two cycles — that is the **Hopf
link**, not a knot, and it is unreachable in play precisely because every move
preserves component count.

`σ₁σ₁σ₁` in `B₂` is the **trefoil**: one component, `u = 1`. It cannot be reduced
to the empty braid by tier-1 or tier-2 moves at all — only a crossing change gets
there, which is the whole point of the unknotting-number mode.

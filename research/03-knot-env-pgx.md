# 03 — Unknotting as a pgx environment

> **Historical: this is the design, not the build.** The environment exists; what it
> actually does is [../docs/representation.md](../docs/representation.md), which is enforced
> in code and checked in tests. Kept for the two things nothing else records: *why braids*
> rather than planar diagrams, and the alternative encodings that were considered and
> rejected.


**Verdict: yes, implementable, with the braid-word encoding.** Planar-diagram (PD/Gauss code)
encodings are painful under JAX's fixed-shape constraint; braid words are not.

## Why braids

A braid word on `n` strands is a sequence of letters `σ_1^{±1} … σ_{n-1}^{±1}`. Its closure is a
link, and by Alexander's theorem every link arises this way; by Markov's theorem two braids have
the same closure iff related by conjugation and (de)stabilization. So:

* **state** = `int8[L]` with alphabet `{−(n−1)…−1, 0, +1…+(n−1)}`, `0` = padding. Fixed shape. ✅
* **moves** are all local rewrites at a position → fixed action space. ✅
* **terminal test** = "word is empty / trivial" → one vectorized reduction. ✅
* everything is `jit`-able and `vmap`-able across thousands of parallel games. ✅

This is the encoding used by *Learning to Unknot* (Gukov, Halverson, Ruehle, Sułkowski) precisely
for these reasons.

## Proposed pgx env: `braid_unknot`

```python
class BraidUnknot(pgx.Env):
    num_players = 2          # Scrambler, Simplifier  (see below)
    N_STRANDS  = 8           # max strands
    L          = 64          # max word length
    # state.word : int8[64]
    # state.n    : int8       (active strands)
    # state.budget_left : int8
```

### Action space (fixed, maskable)

`action = move_type * L + position`, `M × L` actions total.

| move_type | move | effect | preserves knot type? |
|---|---|---|---|
| 0 | free reduction `σᵢσᵢ⁻¹ → e` | shortens | yes |
| 1 | free insertion `e → σᵢσᵢ⁻¹` | lengthens | yes |
| 2 | far commutation `σᵢσⱼ ↔ σⱼσᵢ`, \|i−j\|≥2 | reorders | yes |
| 3 | braid relation `σᵢσᵢ₊₁σᵢ ↔ σᵢ₊₁σᵢσᵢ₊₁` | reorders | yes |
| 4 | Markov destabilization (trailing `σ_{n−1}^{±1}`, appears once) | n−1 | yes |
| 5 | Markov stabilization | n+1 | yes |
| 6 | conjugation / cyclic rotation | reorders | yes |
| 7 | **crossing change** `σᵢ ↔ σᵢ⁻¹` | changes the knot | **no** — this is the unknotting move |

Legality masks are elementwise comparisons on shifted copies of `word` — pure JAX, no branching.
Move types 1, 5 need `len < L`; that constraint is what makes `L` a real design parameter
(hard unknot diagrams *require* temporarily increasing complexity, so `L` must be generous —
budget ~3× the largest instance you intend to pose).

### Two tasks on the same env

1. **Unknotting/simplification** (moves 0–6 only, target = empty word): decide/realize that the
   closure is the unknot. Ground truth free if the instance was generated by inverting these moves
   from the unknot. Reward `+1` on reaching the trivial word, `−ε` per move (shortest path).
2. **Unknotting number** (moves 0–7, minimize count of type-7 moves): gives an *upper bound*
   `u(K) ≤ #crossing-changes`. Reward `= −(#type-7 moves)` on success.

Note the asymmetry that matters scientifically: **upper bounds are certifiable, lower bounds are
not.** A lower bound needs invariants — signature `|σ(K)|/2 ≤ u(K)`, the Alexander/Nakanishi
obstruction, Rasmussen's `|s(K)|/2 ≤ u(K)` from Khovanov homology. These are *not* JAX-friendly;
compute them outside the env, cache them per knot in a table, and use them only in the judge/scorer.
When upper bound = lower bound, the unknotting number is *determined* — that is the publishable
event, and it is exactly what the DeepMind/Oxford work produced for 43 knots ≤12 crossings.

## The 2-player game I recommend building first

**Scrambler vs. Simplifier** — a genuine, finite, zero-sum, perfect-recall-free game:

```
phase 1 (Scrambler, K plies):   start from the empty word (= unknot).
                                apply K type-preserving moves (types 1–6).
                                the closure is STILL the unknot, by construction.
phase 2 (Simplifier, M plies):  sees only the final word, not the move history.
                                wins iff it reaches the empty word within M moves.
payoff:                         Simplifier +1 / Scrambler +1 (zero-sum).
```

Properties:

* **ground truth is free and exact** at every difficulty — the answer is always "unknot";
* the Scrambler's optimal play is *precisely* the open problem "construct hard unknot diagrams";
* it is a clean 2-player zero-sum game, so AlphaZero's theory applies and
  `../pgx-mcts-bench` runs on it with an env swap;
* the difficulty dial is one integer, `K`;
* the "generate is easier than solve" asymmetry is bounded by construction: the Scrambler pays
  for every move it makes, and `M` can be set to `c·K` so the Simplifier is *not* required to
  find the exact inverse path, just any path.

This is the 5-agent league compressed into a 2-player game. Build it, verify the machinery,
then generalize the roles to a population.

## Implementation notes / gotchas

* **Termination is undecidable-ish in the wrong direction.** "Word is trivial" is easy; "closure
  is the unknot" is not (unknot recognition is in NP ∩ coNP, not known to be in P). Always
  generate from a known source so you never need to *decide* it.
* **Canonical form / dedup.** Use a cheap invariant fingerprint (writhe, `n`, length after greedy
  free reduction, Jones polynomial for small instances via an out-of-JAX call) for novelty scoring.
* **Don't let the Simplifier trivially invert.** It doesn't see the history; but if `K` is small
  and moves are mostly type-1 insertions, the inverse is easy. Reward the Scrambler for *diagram
  hardness* (Simplifier's failure), and it will learn to avoid such words on its own.
* **`L` overflow is the real constraint.** If simplification requires exceeding `L`, the instance
  becomes unsolvable in-env, which is an artifact, not mathematics. Log this rate; if >1%, raise `L`.
* pgx's API is `num_players` + `_init` / `_step` / `_observe`; step must be jit-able and
  shape-static. Observation: one-hot the word to `int8[L, 2n−1]`, plus scalar planes for
  `n`, budget, ply. A 1-D residual CNN or a small transformer over `L` tokens is the natural net.
* Cross-check every implementation against an independent, slow, pure-Python knot library
  (SnapPy / `sage.knots` / KnotTheory`) on ≤10-crossing cases. Encoding bugs in this area are
  silent and will produce beautiful, meaningless learning curves.

## As built (M1)

Implemented in `src/rf_knots/`. Differences from the sketch above, and why:

| Sketch | Built | Reason |
|---|---|---|
| `state.word : int8[64]` | `int32[L]` | int8 bought nothing and cost casts everywhere; a batch of 8192 words is 2 MB either way |
| `length` stored in state | recomputed as `sum(word != 0)` | exact because the word is compacted; storing it only creates a way for it to desynchronise |
| move type 7 = crossing change | implemented, masked off in phase 0 and behind `allow_crossing_change` | the action-space *size* is identical in both modes, so one policy head serves both |
| — | `PASS`, always legal | Pgx requires a non-empty mask; also means "scramble less" and "resign" |
| — | start state forced to `n=1`, empty word | the closure of the identity braid in `B_n` is the `n`-component *unlink*; `n=1` is the only trivial knot start |

Action-space size is `3L + 2L(N−1) + 6 + L`. At `L=64, N=8` that is **1158** actions
(insertions are 896 of them), which is between Go 19×19 (362) and pgx chess (4672).

**What is actually verified**, by `rf-knots selfcheck` and the test suite:

1. every move agrees with a list-based Python reference, on every legal action from 120+
   reachable states;
2. every mask bit agrees with the reference legality predicate;
3. every braid-group move (reduce / insert / commute / braid relation) provably preserves the
   element of `B_n` — checked with the **Artin representation on the free group**, which is
   faithful, so this is exact equality in the braid group, not a heuristic invariant;
4. every state has exactly **one closure component** — the invariant that guarantees we are
   always looking at a knot and never at a link;
5. scrambled instances replay back to the empty 1-braid through the JAX environment along a
   BFS-found path.

Two facts worth carrying into M2:

* **Throughput**: 141k env steps/s at batch 8192 on CPU (Apple silicon), ~4.7k games/s. The
  environment will not be the bottleneck; MCTS simulations will be.
* **Random-play baseline**: a uniform-random Simplifier undoes 1.6% of `K=6` tier-0 scrambles and
  0.1% of `K=12` tier-1 scrambles.
* **The difficulty floor**, measured exactly by BFS on tier-0 (`rf-knots calibrate`):

  | `K` (scramble moves) | mean word length | mean optimal depth | max | solved within cutoff 6 |
  |---|---|---|---|---|
  | 3 | 3.6 | 2.56 | 3 | 32/32 |
  | 4 | 4.6 | 3.16 | 4 | 32/32 |
  | 5 | 6.0 | 3.96 | 5 | 24/24 |

  A random scrambler buys about **0.7 moves of difficulty per move spent**, and never once
  produced an instance harder than `K` itself. That is the quantitative form of the objection
  this project started from — random generation is cheap but *uninformative* — and it is the
  number a trained Scrambler has to move. If a trained Scrambler at `K=5` produces instances with
  optimal depth 8+, the proposer game has content; if it stays near 4, it does not.

## Alternative encodings considered

| encoding | fixed shape? | move locality | verdict |
|---|---|---|---|
| braid word | ✅ `int8[L]` | excellent | **recommended** |
| Gauss / DT code | ✅ but moves are non-local, validity constraints global | poor | avoid in JAX |
| PD code (planar diagram) | ✅ `int8[C,4]` | R-moves are local edits | viable, ~3× more code, better for "real" diagram work later |
| grid / arc presentation | ✅ `int8[G,2]` | grid moves are clean and finite! | **strong second choice** — grid diagrams have a genuinely finite, well-understood move set (cyclic permutation, commutation, (de)stabilization) and are used in Heegaard-Floer computations |

If braid words disappoint, grid diagrams are the next thing to try, not PD codes.

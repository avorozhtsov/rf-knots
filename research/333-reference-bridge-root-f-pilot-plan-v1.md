# Reference-bridge root F pilot: prospective design gate

2026-10-11. The independently audited root-from-scratch b64 micro-pilot on the new high-CC TRAIN roots found 0/8 solutions after 670.833 CPU seconds. This note specifies the **next proposed TRAIN-only pilot**, not a launched search or a claim that the 32 candidates provide F labels. The immutable bank remains at 399 distinct F-usable roots.

## Search and leakage boundary

For each selected TRAIN root, independently replay the constructive reference and record its exact braid states and remaining verified suffix costs. A new canonical-pgx MCTS variant may explore from the root under an actual local simulation budget. A rollout is completed only if it reaches the unknot normally or reaches an exact reference state and then replays that state's suffix action by action to the unknot. Record the generated prefix, the suffix provenance and the entire completed path; independently replay from the original root and recompute CC, moves and both objective costs. Do not label a cap-exhausted search as a losing action.

Only comparisons between two **completed**, replayed paths with different legal first actions and a strict objective-cost margin at the **exact original root** may yield F coefficients. Join at the root itself, an immediate undo/redo loop, repeated exact states before the join, and a prefix that merely inserts then deletes a cancelling pair are excluded. Shared-prefix divergences after the root yield no root-only F signal. Intermediate states, even when traversed by a valid completed path, are neither training examples nor negatives; this is essential because their invariant-owner groups may be held out. The ownership, exclusions and exact-state limitations of `research/327-root-only-f-supply-and-leakage-contract-v1.md` remain unchanged.

## Freeze before execution

Implement the bridge as a **new versioned source**, leaving every previous SHA-pinned teacher untouched. Pin source, canonical pgx dependency, roster/audit SHA, frozen R2 endpoint, root selection, seeds, objective caps, true local simulation budgets and join rules before running. A small balanced panel should contain equal stage-2/stage-3 and CC-cap strata, with both L10/L1000 and independent seeds; do not select roots by observed neural search score. First run a unit/smoke case with a known legal bridge and a deliberately invalid cancelling loop, then one real shard with SHA/full replay, then resume. Save each attempt and a resumable manifest. Independently audit every shard, ownership, all completed bridges, objective costs, exact root-action divergence, exclusion rules, CPU, wall time and neural evaluations. Report distinct new F-usable roots and CPU per root by stage/objective, not candidate/seed counts.

This pilot must have an explicit CPU ceiling and a prospective stop/go yield threshold before launch. If no nontrivial completed root forks arise, stop this recipe and investigate a different TRAIN source family; do not silently relax the leakage boundary or scale to 30,000 candidates. Only audited new F groups can enter a new immutable additive bank that preserves all existing 399 roots. No optimizer hot-swap, viewed DEV/TEST150 selection, unknotdb mutation/publication, cloud purchase, commit, merge or push.

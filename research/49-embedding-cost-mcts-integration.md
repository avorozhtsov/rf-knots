# Embedding-priors для cost-MCTS: инженерная интеграция

2026-09-21. Продолжение контракта 48. Не независимый научный тест, не новый
training run и не выбор параметров на TEST.

При открытии допустимых действий вычисляем embedding каждого child после
точного действия над исходным словом. Приоритет P(a|s) пропорционален
exp(−d(child, unknot)/τ), где τ=1 фиксируется до запуска. Это эвристический
prior, не вероятность успешного действия. Нормализация вычисления exponent
и предел −690 защищают от численного underflow; рёбра не получают нулевую
вероятность только из-за переполнения. Отсечение по embedding запрещено.
Нормализованное глобальное представление кешируется в существующем
KnotDistanceHeuristic; локальные позиции применяются к raw word.

Расстояния вычисляются только для открытых lazy/progressive действий.
Каждый запрос, action-score и реальный вызов embedding учитываются отдельно;
повторный score кешированного состояния не объявляется новым независимым
узлом. Старый probability-value не используется. Utility и incumbents —
по контрактту 48. Encoder и metric objective загружаются без изменения весов.

## Фиксированная инженерная диагностика

- Данные: TRAIN `embedding-diverse-short-u-corpus-v1/corpus.json`, SHA
  `f3655e7dbfcc5b6ec7448b1f747dc2a4e1235fe036ab07fec61cc18df05c8f14`.
- До scoring выбрать по порядку первый ещё не выбранный record для четырёх
  условий: любой; L>=96; N>=12; L>=96 и N>=12. Если условие невыполнимо,
  остановиться, не подменять размер. Это четыре представления, не обещание
  четырёх независимых knot identities. Все reference witnesses replay.
- Общие условия: λ=1000, seed=20260921, 512 симуляций на корень,
  widening_batch=4, c_puct=1.5, без root noise и learned proposals.
- Ресурсные caps одинаковы для трёх arms и вмещают reference witness;
  не выдавать witness-подсказки как успех на неизвестных ресурсах.
- Arms в фиксированном порядке: uniform, parent, candidate. Parent и candidate
  — завершённые checkpoints эксперимента 47 с фиксированными SHA.
- В отчёте: выборка до inference, source/input pins и snapshot, шаги/время,
  action-scores/embedding-evaluations, все incumbents, replay witness либо
  отсутствие решения. Без раннего окончания всей серии из-за хороших/плохих
  результатов; без изменения τ по наблюдаемым успехам.

Задача диагностики — проверить исполняемость, расходы и достижимость глубины
при данном prior, а не решить вопрос научной полезности на четырёх TRAIN
примерах. Нулевые успехи не опровергают embeddings; положительные успехи не
дают generalization evidence. После инженерного анализа нужен отдельный
новый протокол с budgeted продолжением/перепланированием, новым TEST и
согласованным учётом вычислений. Миллионный RL-цикл этим не заменён.
